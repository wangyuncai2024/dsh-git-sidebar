# dsh-git-sidebar

DSH 的 **Git 侧边栏插件**：把 Git 面板做成右侧栏（rightbar）里的**一等标签**，
与内置的「工作区文件」「新建终端」「浏览器」并列。

这是 `dsh-git-panel`（右下角悬浮面板）的**侧边栏版**。两者是**两个独立的插件**，
目标是由本插件**取代**旧的那个（右下角浮窗要彻底移除）。过渡期若要两个都装，
注意模型工具会撞名——见下面「已知限制」。

---

## 界面（v0.3.0：按「一屏只画一件事」重新设计）

面板不是一条从头滚到尾的纵向长流，而是 **上下文条 + 表面切换 + 停靠动作条** 三段：

```
┌─ 上下文条 ────────────────────────────────┐  我在哪儿（常驻，不随表面切换）
│ ⑂ fork-local.2  ↑2↓1  → fork/local.2   ⟳ ?│
│ ▤ D:\…\dsh-skills-manager      切换 ✓跟随 │
├─ 表面切换 ────────────────────────────────┤  一屏只画一件事
│ 改动 ⑤ │ 历史 │ 分支 ② │            ⚙ 设置 │
├─ 提示条（有内容才占高度）─────────────────┤  操作结果 / 失败补救
│ ✓ 已提交 4a1c8e2 · 已推到 fork/local.2  ✕ │
├─ 表面正文（自己滚，唯一的滚动区）─────────┤
│                                           │
├─ 提交区（停靠，只在改动表面）─────────────┤  提交框紧贴动作条
│ [提交信息…………………]  [✓ 提交]             │
├─ 动作条（停靠，内容由状态推导）───────────┤  一屏一个主操作
│ [＋全部暂存] 拉取 推送  更多▸               │
└───────────────────────────────────────────┘
```

**为什么这么改**（实测，`git --porcelain` 现场 5 个文件有改动）：

| | 旧版面（一条长流） | 现版面（表面切换） |
| --- | --- | --- |
| 832px 高的框里 | 内容 scroll=881 / 可视 728 → **开局就要滚 153px** | **0 滚动**（surface 594–614 ≈ 可视） |
| 再展开分支 + 远程 | scroll=1317 → **1.81 屏** | 各在自己的表面里，各自 0 滚动 |
| 「最近提交」 | 248px 硬上限，300px 下只看得到 3 条 | 8 条全可见（无上限，表面自己滚） |
| 滚动区层数 | **3 层嵌套**（正文 / 清单 / diff） | **1 层**（表面） |

四条设计立场：

- **动作条由状态推导**（`deriveActions`，纯函数可测）：脏工作区 → 主操作是「全部暂存」；
  已暂存 + 落后 → 「拉取」；冲突 → 「全部标记已解决」。**全部能力仍然可达** ——
  低频与不可逆的（撤销暂存 / 丢弃改动 / 变基 / stash）收在「更多」里，
  动作条只做**排序**、不做**过滤**。
- **网络加速与远程仓库搬进「设置」表面**。加速原先在比「改动」还靠前的位置；
  它「解释为什么连不上」的理由成立，但该在**失败时**推到眼前 —— 现在失败提示条
  里有「去设置」直达按钮（`lib/failure.js` 的文案也据此改了）。
- **删掉底部状态条**：它与头部上下文条信息高度重叠（分支 / 上游各说两遍，一次在屏外）。
  领先 / 落后收成头部一颗 `↑2↓1` 胶囊。
- **diff 是一整块表面**：点改动行 → 宽栏左列表｜右 diff 并排，窄栏 push 导航
  （`‹ 改动` 返回）。顶上有「未暂存 / 已暂存」两档 —— 那是**同一个文件的两份不同
  diff**（`git diff` vs `git diff --cached`），旧版面要看到另一份得先暂存/取消暂存、
  把行翻个面再点一次。diff 打开时提交区收起（此刻用户在看改动，不是要提交）。
  diff **不是第五个 tab**：它是「改动」档里的一层视图，切走时一起收起。
- **容器查询而非媒体查询**：右侧栏宽度是用户**拖**出来的（300px–视口 70%），
  同一个窗口里既有窄态也有宽态。断点在 339px / 559px / 560px 三档（见 `PANEL_CSS`）。

## 它长什么样

1. 点右侧栏的「+」→ 出现功能列表（工作区文件 / 新建终端 / 浏览器 / **Git 面板**）。
2. 点「Git 面板」→ 它作为**一个标签**占据右侧栏，成为主工作区的一部分。
3. 标签可以像其它标签一样：分屏、拖出来浮动、关闭、随会话切换。

**没有右下角浮窗了。** 旧版那个自己管位置、尺寸、最小化胶囊的浮层，在这一版里
彻底移除——位置、尺寸、停靠/浮动/分屏全部交给右侧栏的 docking kit，插件只往
给定的框里画内容。

## 安装

```bash
cd <本插件根目录>
dsh plugin --profile web add "link:$PWD"
# 首次安装 / 卸载后要重启一次 dsh（bundles 是启动时读的）
```

卸载：

```bash
dsh plugin --profile web remove dsh-git-sidebar
```

零依赖（`dependencies` 为空），只用 Node 内置模块，因此 link 安装到任何 profile
都能解析。

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `defaultDir` | `''` | 面板默认操作的目录；留空 = 跟随当前会话工作目录 |

## 它是怎么接进右侧栏的（本插件最核心的部分）

DSH 的右侧栏标签是**三段式注册**，缺一不可：

| # | 注册点 | 作用 |
| --- | --- | --- |
| 1 | `ctx.sidebarRightTabs.register({ id, kind, priority, title, guide })` | **声明这是一种什么标签**。「+」列表里那一项就是它（`guide` 数组） |
| 2 | `sidebar.right.pane.tab`（keyed，key = 上面那个 `id`） | 标签**正文** |
| 3 | `sidebar.right.pane.tab.title`（keyed，同 key） | 标签**标题**（可省；省了用 registry 捕获的标题） |

三段必须用**同一个 id**，所以它在 `lib/client.js` 里只写一次（`GIT_TAB_ID`）。
`id` 取包名（官方那几个标签也这么做），因为它在**所有注册里必须全局唯一**；
`kind` 才是 `openTab('git')` 用来点名类型的判别子。

关键常量（`lib/client.js` 顶部）：

```js
const GIT_TAB_ID = 'dsh-git-sidebar'   // 全局唯一，也是两个 keyed 插槽的 key
const GIT_TAB_KIND = 'git'             // openTab('git') 用
const GIT_TAB_PRIORITY = 'extension'   // 产品之外的插件用这一档（也是最高档）
```

需要声明的客户端服务：

```js
const inject = ['slots', 'sidebarRightTabs', 'sidebarRight', 'uiWorkspace']
```

> `sidebarRight` 与 `sidebarRightTabs` 由右侧栏用 `ctx.reflect.provide` **动态提供**，
> 不在 Inspect 的服务目录里（那份目录是手写白名单）——但 `ctx.get('sidebarRight')`
> 取得到，而且**必须写进 `inject`**：客户端服务是 cordis 懒注入的，不声明的服务
> 在插件上下文里读不到。这与 `uiWorkspace` 是同一个坑。

「设置 → 通用 → Git 面板」那一行里还有个「打开」按钮，走
`ctx.sidebarRight.openTab('git')`——它同时会把右侧栏展开（内容看不见就不算打开）。

## 与 dsh-git-panel 的关系

|  | `dsh-git-panel` | `dsh-git-sidebar`（本插件） |
| --- | --- | --- |
| 挂载点 | `shell.overlay`（右下角浮层） | `sidebar.right.pane.tab`（右侧栏标签） |
| 位置 / 尺寸 | 插件自己管（fixed 定位 + 拖拽改宽 + 最小化胶囊） | 宿主右侧栏的 docking kit 管 |
| 宿主侧 git 逻辑 | 一套 | **复制**了一份，各自独立演进 |
| 路由 | `/git-panel/*` | `/git-sidebar/*` |
| 模型工具 | `git_status` / `git_add` / … | 同名（`git_status` / `git_add` / …） |

**宿主侧代码（`lib/git.js` / `ops.js` / `routes.js` / `net.js` / `log.js` /
`help.js` / `failure.js` / `util.js` / `tools.js`）是从 `dsh-git-panel` 复制来的**，
按「复制一份，新仓库自包含」的选择。因此这个仓库可以独立安装、独立运行，
代价是两份宿主代码会各自演进——等侧边栏版稳定后再废弃旧的。

路由已经加了 `/git-sidebar/` 前缀与旧插件区分开。模型工具名仍是同一套（见下面
「已知限制」里那条已查清的撞名行为）——**过渡期建议先卸掉旧插件**。

## 界面：按侧边栏重新设计（历史记录：v0.1–v0.2 的版面）

> **这一节描述的是 v0.3.0 之前的版面**（一条纵向长流 + 折叠区块 + 底部状态条）。
> 它已经被上面的「一屏只画一件事」取代，保留在这里是因为其中**语义层**的修复
> （中文路径转义、相对时间、ref 徽章、窄栏下分支名被挤没……）**全部带进了新版面**，
> 而那些修复的来龙去脉只有在这里读得全。

旧浮窗的版式是为「360px 固定宽的角落小窗」设计的；右侧栏是**常驻的全高工作区**，
宽度用户可拖（`RIGHTBAR_MIN = 300px`，默认约视口 45%，上限 70%，
见 `packages/client/ui-layout/src/client/columns.ts` 与 `stores.ts`）。
两个容器的信息架构本来就不同，所以这一版没有照搬，而是按侧边栏重新组织：

- **头部 = 上下文条**（不再是「🐙 Git 面板」大标题）：右侧栏的标签栏已经写着
  Git，正文再画一遍标题是重复。头部两行回答「我在哪儿」——
  `分支名 → 上游 领先/落后` + 目录（切换 / 刷新 / 跟随会话在行尾）。
- **第一屏给日常动线**：改动 → 提交 → 同步（拉取 / 推送 / 获取远程 / stash）
  依次排开，打开标签即见。
- **分支管理与远程配置默认折叠**：两者是「找分支」「配一次管很久」的低频操作，
  各自只剩一条可点的区块头（带 ▸/▾ 箭头）；远程区块在编辑中 / 出错 /
  有重复远程时**自动展开**——配置的问题不能藏在收起的区块里。
- 最近提交与提交详情垫底；命令结果与待选项仍然固定在正文滚动区之外（不随滚动消失）。

窄栏适配（300px 最窄档）沿用实测驱动的做法，已经按实测修掉的问题：

- **分支名在窄栏下被挤没**（真缺陷）。300px 下不换行时，固定宽度的那一列控件先占位，
  分支名被压到 **28px**，渲染成 `for...` / `f...`。头部上下文条与本地分支行都是
  **可换行**版式（`S.rowWrap` / `S.rowMain` / `S.rowAside`）：左半占满整行，
  右半在放不下时整组掉到第二行，分支名因此拿到整行宽度。

### 视觉打磨（本轮：强调色、头部版式、窄栏三处回归）

这一轮只动观感与排版，不改信息架构，也不新增控件。逐条：

- **装饰色从「品牌色」换成「强调色」**。宿主的 `--dsw-alias-brand-primary` 在
  **浅色主题下就是近黑**（`#0f1115`），而面板把它用在 2–3px 的细装饰上（头部顶端那道
  身份条、每个区块标题前的短杠、展开行的定位条、选中行）——细黑线读起来像分隔线或
  错误提示，不像强调。实测顶条原本渲染成 `#16181c`。
  现在这三处统一走面板自己的 `--dgs-accent`，取值是宿主的
  `--dsw-alias-state-business-primary`（浅 `#4176e6` / 深 deepseek-400）——那才是宿主
  给**交互强调**用的档位，面板的焦点环本来就跟着它走，于是装饰与焦点是同一种蓝。
  **实心主按钮仍走 brand-primary**：那是宿主按钮的既定配方（浅色近黑、深色近白），不动。
- **强调色的文字档 `--dgs-accent-text`**：饱和的强调蓝当 11px 小字、压在同色 8% 的
  浅底上只有 **3.84:1**（浅色主题，实测），过不了正文阈值。所以「有改动」的摘要胶囊文字、
  `.dgs-current-tag`、`hot` 按钮（脏工作区下的「安全拉取」）的文字色都走这一档 ——
  与服务端那三个文字档同一套做法：把强调色朝**当前主题的前景色**压 40%（浅色压暗、
  深色提亮）。同一层底上实测 **7.29:1**（浅）/ **7.29:1**（深，取面板底那一层，是两边
  更紧的）。不支持 `color-mix` 的引擎由 `@supports` 退回 —— 那一支退回的是
  **`brand-primary`（随主题翻转的前景色档）**，不是「生」的强调蓝：后者当 11px 文字压白底
  只有 4.23:1、压胶囊底 3.84:1，都过不了。写死一个蓝色 hex 也不行，同一份 CSS 要同时
  服务深浅两个主题。
- **头部改成「主体 + 行尾控件」两段**。原先是「一个可换行的行 + spacer + 控件」：
  300px 下主体先占满整行，spacer 把控件组整体挤到第二行 —— 头部那两个图标（🌐 / ?）
  就孤零零挂在分支名下面一行。现在每行是 `headTop` = `headMain`（可换行、可收缩）
  + `headRail`（固定宽度、不参与换行），控件组始终钉在本行右侧，换行只发生在主体内部。
  两条上下文行之间补了一道 1px 内分隔（`.dgs-ctx-sep`）。
- **头部与正文的分界改用 `border-l2`**（浅 .10）而不是 `border-l1`（浅 .04）。两者底色
  同为 `bg-layer-2`（浅色主题下三层 `bg-layer` 全是纯白），分界只能靠描边；.04 的黑几乎
  看不见，头部与正文会糊成一整块。
- **收起的折叠区块不再是个空盒子**。『本地分支』『远程仓库』收起时卡片里只有一行 11px
  标题，用 `S.card` 的 9px 内边距会撑出约 40px 的空盒，读起来像「这块没加载出来」。
  新增 `S.foldCard`（纵向内边距 5px，其余与 card 相同），收起态降到约 28px；展开后
  仍回到 `S.card`。
- **「仓库页 ↗」不再带下划线**。它是 `<a>`，宿主全局样式会给 `<a>` 加下划线，而它与
  紧挨着的 `<button>` 是同一排同类控件——一排里只有它带下划线，看着像正文链接混进了
  按钮组。现在显式 `text-decoration:none`，**悬停时才**出现下划线（只给 `a.dgs-btn`）。
- **关掉开关的空态垂直居中**（那一态是纯说明、没有可点的东西）；「还不是仓库」空态
  不动 —— 它下面有按钮，必须从顶部顺着读。
- **面板自己的「下拉空白」防呆**：宿主没回 `candidates` 时（旧宿主 / 配置还没读到），
  镜像下拉至少渲染一条禁用占位项，而不是一个没有任何 `<option>` 的空白控件。

窄栏下另外三处**实测发现并修掉**的问题（都不是本轮引入的，是照着 300px 截图查出来的）：

- **「拉取自 / 推送到」两行的下拉被压成一个箭头**。`flex:0 1 auto` 且没有下限时，
  固定的按钮与长说明先占位，下拉被压到约 **20px**：值文本（「跟随上游」）整个消失，
  只剩一个孤零零的箭头 —— 这一行的主信息反而最看不见。现在这两行走 `S.pickRow`
  （可换行）且下拉有 **84px** 下限（`S.targetSelectMin`）。
- **那两行尾部的来源说明会从面板右边溢出去**，让正文区出现横向滚动。它原先用
  `S.note`（`flex:0 0 auto`，按内容宽度占位、不缩）。改用 `S.targetNote`
  （`flex:1 1 auto; minWidth:0`），窄栏下代价只是这一行变成两行。
- **头部图标按钮与目录动作按钮不同高**（26px vs 20px），一排控件里基线被顶歪；
  现在 `S.mini` / `S.miniLink` 与 `compact` 档对齐。

### 「最近提交」行：ref 徽章把提交标题挤没了

现场（真实截图）：一条提交挂着 4 个引用
（`HEAD -> master, tag: dsh-v0.2.1-alpha.1, origin/master, origin/HEAD`），
整个「最近提交」列表只剩被截断的 `Merge pull reques…` —— **标题等于没有了**。
根因是这一行把所有元素挤在一条线上，而徽章/时间/按钮都按内容占宽：
4 个徽章先吃光宽度，标题（唯一可伸缩的那个）就被压到 **0 宽**。
「这一条提交是什么」恰恰是这个列表最该看清的东西，却第一个被挤没。

三处一起改，缺一不可：

- **每行拆成两层**（`S.logRow` 用 grid 三列 + 一行 `logMetaLine`）：
  第一层是「哪条提交 + 对它做什么」（哈希 / 标题 / 「切到此」），
  第二层是「挂在哪些引用上 + 谁什么时候提交的」。标题落在
  `minmax(0, 1fr)` 那一列，**独占该列宽度**，不再和徽章抢。
  第二层跨满整行（`1 / -1`）—— 只给它标题列的宽度时，300px 下这一层
  独占 **4 行**、行高冲到 118px，一屏只剩 1 条提交。
- **一行最多内联 2 个 ref 徽章**（`LOG_REF_LIMIT`），其余折成 `+N`，
  悬停给出全量。**不重排**：直接用 git 装饰串自己的顺序 ——
  `--decorate=short` 本就是 HEAD → 本地分支 → tag → 远程跟踪引用，
  越靠前越是「这条提交自己的东西」，取前 N 个就已经是优先级。
- **提交清单的高度上限单独放宽到 248px**（`S.logList`）。`S.list` 的 148px 是给
  单行列表定的，而提交行现在是两层（实测首行 50~72px）——沿用 148px 时
  一屏只看得到 2 条，本末倒置。

顺带修掉一个**一直没生效**的老 bug：`relativeTime` 原先写的是
`Date.parse(text.replace(' ', 'T'))`，而 git `%ai` 换成 T 之后
（`…T10:00:00 +0800`）`Date.parse` 返回 **NaN** —— 偏移前带空格、且缺冒号都不是
合法 ISO（只有 `…T10:00:00+08:00` 解析得出）。于是「3 天前」这一档**从来没生效过**，
提交行里一直显示最占宽度的绝对日期。现在补上冒号再解析；仍解析不了才退回绝对日期。

三条用例（`test/client.test.mjs`）：4 个引用时标题不被挤没且 `+N` 点名收起了哪两个、
只有 2 个引用时不出现 `+N`、`relativeTime` 要解析出相对时间。都做过**反向验证**：
把徽章上限改回 `99`、把解析改回「只换空格」，对应用例各自变红。

另外**试过又撤掉**的一处，记下来免得将来重复踩：`S.code`（状态码小徽章）加过一条
`inset 0 1px 0 rgba(255,255,255,.5)` 的内高光。浅色主题下看不出来（底本来就是
`#f9fafb`），深色主题下却在那块 `#1b1b1c` 上画出一条**近白的顶边**（实测 `#f9fafb`）——
22px 宽的小块上那条白线比里面的状态码还抢眼，像渲染毛刺。**深浅两侧都要成立的东西
才配留在面板里**，所以撤掉了。

本轮验收（下面这条是「视觉打磨」那一轮的记录；最近一轮见上一节）：
`npm run check && npm test` 全绿（335 tests / 332 pass / 3 skip），
`audit-all.ps1` 在 3 状态 × 2 宽度 × 2 主题共 12 组下 **FAILS=0**。

这轮还加了**两条钉住强调色取值链的用例**（`test/client.test.mjs`）——因为这里有一个
我自己踩过、且**只在某一条分支上**才会暴露的坑：

- `--dgs-accent-text` 的**兜底链**不能退回「生」的强调蓝。`color-mix` 那一支是对的
  （朝前景色压过），但 `@supports not (...)` 那一支最初就退回了生色 —— 白底 4.23:1、
  胶囊底 3.84:1，**11px 正文两条都不过**。三条内联兜底同样犯了。现在整条链（CSS 变量
  定义 + `@supports` 支 + 三处内联兜底）都退回 `brand-primary`（随主题翻转的前景色档：
  浅 #0f1115 → 18.9:1、深 #f9fafb → 13.0:1）。**写死一个蓝色 hex 是错的**：同一份 CSS
  要同时服务深浅两个主题。
- `--dgs-accent-tint` 的百分比（8%）与各处 `rgba(37,99,235,.xx)` 兜底必须同值。
  早先焦点环那一处写的是 `.16`，与定义对不上。

两条用例都做过**变异测试**：把兜底改回生色、把焦点环改回 `.16`、把内联兜底改回生色，
它们各自都会失败。断言只盯「替 `--dgs-accent-tint` 兜底」的那些值，不全文扫
`rgba(37,99,235,...)` —— diff 区块的行底（hunk 底 `.08` + `color-mix 10%`）与闪烁动画的
`.35` 属于**别的调色板**（diff 行底 / 一次性脉冲），早在 HEAD 就存在，一起断言只会造出
一条假失败。

## 开发

```bash
npm run check   # 语法检查（node --check 全部 lib/*.js）
npm test        # 全部测试（node --test）
```

**换机器、换 DSH 版本时先跑一次 `npm test`。** 它覆盖的是插件自身的加载与注册
契约；这些一旦坏掉，通常表现为「插件装上了、界面里却没有」，静默且难查。
其中 `test/client.test.mjs` 专门盯住右侧栏的三段式注册与新版面的结构：

- 三段注册都发生了，且**正文与标题用同一个 key**；
- 类型定义的 `id` / `kind` / `priority` / `guide` 都对（`guide` 的 `order` 要排在
  官方 `files 10 / terminal 20 / browser 30` 之后）；
- 拿不到标签注册表时，正文与标题**仍然注册**（故障要「少一块」而不是「全没」）；
- 标签类型注册失败会带**真实原因**回报宿主日志（不静默、不谎报成功）；
- 标签正文铺满给定的框、**不再是固定定位的浮窗**（`position` / `zIndex` / `right` /
  `bottom` / `boxShadow` 都不该有）；
- **一屏只画一件事**：四个表面各自渲染（`openSurface` 助手按档位进入），
  只有当前那一档在树里；
- **上下文条在表面滚动区之外**（滚走了就等于没有），且带着分支 / 上游 /
  `↑领先↓落后` 胶囊；
- **清单不再自带滚动条与高度上限**（`S.list` / `S.logList`）—— 每个表面只有
  **一个**滚动区，这是把三层嵌套滚动减成一层的那条断言；
- **diff 是一等表面**：点改动行后渲染 `dgs-split`（左列表｜右详情），
  diff 本体在**详情栏**里而不是改动清单的子树里；「未暂存 / 已暂存」两档会带
  正确的 `cached` 各取一份；
- **动作条由状态推导**：脏工作区 → 主操作「全部暂存」，已暂存+落后 → 「拉取」，
  已暂存 → 「推送」，干净 → 「获取远程」；同一排里不出现两个同名动词；
  「更多」里保留兜底能力（撤销暂存 / 丢弃改动）；
- **提示条（命令结果）在表面之外**、可「清空」收起；
- **窄栏下分支名不被挤没**：「分支」行与本地分支行都是可换行版式（左半占满整行，
  右半整组换行），分支名带 4em 最小宽度；
- 旧版浮窗遗留的 localStorage 键会被清掉。

**测试是怎么跟着改版的**：这次改版有 43 条用例直接依赖被删掉的结构
（`dgs-status` 状态条、`dgs-fold-head` 折叠头、默认渲染的远程行 / 提交历史）。
处理方式**不是删断言**，而是在助手层换入口 —— 新增 `openSurface(tree, react, '分支')`
一类的导航助手，把 `openBranchManager` / `openRemotesSection` / `openNet` 三个
（共 31 处调用点）改成「先切表面」；下面的 `opPayloads` 断言本来就是与表面无关的，
一行都不用动。**语义没有降低**：例如「窄栏下分支名不被挤没」仍然是同一条断言，
只是先切到分支表面。

顺带修掉的一个**假通过**陷阱：几条「不该出现 X」的断言（例如「没有重复远程时不该
有警告行」）在远程行搬进设置表面后会**永远为真** —— 树里根本没有那一块。
现在这类用例都先切到对应表面、并先断言「前置条件真的画出来了」。

这两条窄栏用例做过**变异测试**：把 `S.rowWrap` 换回不可换行版式，它们会失败。

## 融合升级（v0.2.0：吸收 DSH-better-sidebar 与生态插件的优点）

本轮按调研结论（omdsh-dev/DSH-better-sidebar 的 Git 视角 / diff 栈 + dsh-git-plus、
dsh-solution-explorer、dsh-better-sidebar-svn 等生态插件）做了一轮融合，逐条：

**工程卫生（一行级，收益即刻）**

- 每条 git 命令统一带 `--no-pager -c color.ui=false -c core.quotePath=false`：
  **中文 / 空格路径原样显示**，不再出现 `"lib/\346\226\207\346\241\243.js"` 这种八进制转义
  （此前中文文件名在改动清单与 diff 里全是乱码形态）。
- `status` 改用 **`--porcelain=v1 -z`**（NUL 分帧）：文件名里的空格、换行不再把清单切碎；
  重命名（R/C）条目的原始路径 token 正确消费。
- `show` 与「切到此提交」加 **`--end-of-options` 哨兵**：调用方回传的提交号永远不可能
  被解析成 git 选项（`rev: "--output=NUL"` 这类 flag 注入在哨兵处停下、失败而不是写文件）。

**界面升级**

- **变更列表升级为目录树**（VS Code SCM 同款）：单子目录链压缩成一行
  （`src/client/changes` 不再是三层各占一行）、目录行可折叠、带下级变更数胶囊、
  目录行直接给「暂存目录」（`git add -A -- <dir>`，一次收下整个子树）。
- **diff 渲染升级**：连续的删块/增块配对成「改」（蓝色行），配对行做
  **行内字符级高亮**（真正变了的那几个字加深色小片）；≥8 行的连续上下文
  折叠成「… N 行」，点击展开（不发请求，内容已在）。
- **合并冲突可见**：porcelain 里的 UU/AA/DD 条目在状态里单列 `conflicts`，
  清单顶部出横幅（要做什么 + 是哪些文件），冲突行带「冲突」徽章。
- **提交历史升级**：每行带 refs 徽章（`HEAD -> main`、tag）与作者 + 相对时间
  （「3 天前」）；满一页（8 条）时出现「加载更多」，每次向后翻 20 条
  （`log --pretty=format:%h%x1f%s%x1f%an%x1f%ai%x1f%D` 结构化分页，本地查询）。
- **标签角标**：右侧栏标签 chip 上实时显示未提交改动数（`Git · 3`），
  干净时就是纯「Git」零噪音。
- **「藏起当前改动」**：手动 `git stash push -u`（安全拉取/安全切分支的自动藏之外，
  主动想把工作区清干净的场合）；备份照旧进「stash 备份」区收尾。

**测试**：新增 16 个用例钉住以上行为（parseStatusZ 的 NUL 分帧与中文路径、
isConflictCode、logPage 的 argv/解析、addDir、目录树折叠/压缩、冲突横幅、
标签角标、diff 配对与折叠、stashPush）。`npm run check && npm test` 全绿
（333 tests / 330 pass / 3 skip——skip 的是需要真 git 且沙箱受限的用例）。

**未吸收（与调研结论一起明确不做）**：AI 生成提交信息（需要宿主模型通道，待宿主
暴露 API 后再加）、`@文件` 引用进输入框（同）、多仓库/worktree 下拉（当前单仓库
场景优先级低）、提交图谱（SVG 泳道，属 v2）。

## 已知限制 / 待办

- **过渡期两个插件同时安装时的工具撞名**（已查清，非未决）：
  `packages/core/tools/src/index.ts:746` 的 `NamedEntries` 在重名时抛
  `tool "<name>" is already registered`（`packages/core/scope/src/store.ts:43-46`）。
  因为本插件的 `registerTools` 有 try/catch（见 `lib/tools.js`），结果是：
  **谁先注册这 13 个 `git_*` 工具，就归谁**；后注册的那一份每个工具都会记一条
  「注册工具失败」的日志，然后被跳过。功能上无差别（两个插件跑同一套宿主 git 逻辑），
  但有个**卸载顺序的坑**：后注册者一个工具都没成功注册，所以卸掉先注册的那个插件后，
  这些工具会消失，直到后注册者重新 apply / 重启。
  之所以**不**把它们改名成 `git_sidebar_*`：目标是侧边栏版**取代**旧插件
  （「右下角的悬浮面板就彻底移除」），终态只剩本插件时 `git_status` 这个名字才是对的，
  改名只会带来一次无谓的迁移。若在过渡期要两个都装，建议先卸掉旧插件。
- `panel` 只暴露 `id`，**没有** docked / floating 字段；浮动态只能靠 `tab.visible`
  与 `sidebar.fullscreen` 间接推断。目前面板不需要这个信息，故未处理。
- 界面文案是中文硬编码，没接 `ctx.locale` 词典体系（官方那几个标签走 locale 是
  为了多语言；本插件暂时不需要，`title` 是 thunk，将来要接只需改一处）。
- 本轮改造**尚未在真实 DSH 里加载验证**，只到「假 window + 假 React 跑真实
  bundle」+「headless Chrome 按真实主题 token 量版面」两层。首次安装后请按下面
  「验收清单」在界面上确认一遍。
- 窄栏（300px）下仍有少量次要文本用省略号截断（远程地址、提交标题、`↩ 本地 master`
  这类注解）—— 这是**有意**的：它们都有 tooltip 给全量，而强行换行会把每行撑成两三行，
  反而更难扫读。已修的是「分支名」这种主信息。
- **表面切换的记忆不持久**：`surface` 只活在会话状态里，切仓库 / 重载页面回到「改动」。
  这是有意的（改动是默认动线），但如果用起来觉得「我总是在历史页」，可以再加一个
  localStorage 记忆 —— 现在不做，避免又多一个要维护的界面偏好。
